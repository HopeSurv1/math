# 反思機制開／關比較實驗

專刊表 1 用的實驗：比較「沒有反思機制」和「有反思機制」時，老師回覆出問題的題數和回覆時間。

## 不用切換反思機制的開關

反思機制在檢查出問題時，會把改寫前的原稿存起來。所以每題只要跑一次，就同時拿到兩個版本：

| 版本 | 是什麼 |
|---|---|
| 無反思 | 反思機制檢查前的原稿 |
| 有反思 | 學生最後看到的回覆（檢查通過就跟原稿一樣；有問題就是改寫後的版本） |

兩邊比的是同一份原稿，比分開跑兩次更公平，API 用量也省一半。實驗腳本會自動打開反思機制，不用改 `.env` 的 `REPLY_REVIEW`。

## 步驟

### 0. 準備
專案根目錄要有 `.env`，裡面填好 `GEMINI_API_KEY`（把 `.env.example` 複製成 `.env` 再改）。

### 1. 跑實驗
```powershell
py experiments/reflection_eval/run_experiment.py
```
- 100 題大約需要 250 次 API 呼叫（每題 2～3 次）。主要模型免費方案一天只有 20 次，建議老師回答也改用備援模型：
  ```powershell
  py experiments/reflection_eval/run_experiment.py --chat-model gemini-3.5-flash-lite
  ```
  論文裡要寫明實驗用的是哪個模型（結果檔的 `chat_model` 欄位有記錄）。
- 可以分好幾天跑：跑過的題目會自動跳過；連續 3 題失敗（額度用完、模型塞車）會自己停下來。
- 前後用的模型要一樣：之前跑過的題目用的模型跟這次不同時，程式會警告（結果混在一起不能比）。
- 只重跑某幾題：`--only A01 B02`。

結果存在 `results/raw.jsonl`；這次實驗畫的圖搬到 `results/images/`。實驗用的是 `results/experiment.db`，不會動到網站的資料庫。

### 2. 產生判讀網頁
```powershell
py experiments/reflection_eval/make_sheet.py
```
產生 `results/judge.html`（已經有舊的判讀檔時要加 `--force` 才會重做）。

- **預設**：回覆A 固定是原稿（無反思）、回覆B 固定是最後回覆（有反思）。判讀的人知道哪個是哪個，**不是盲測**，專刊要寫明（例如「判讀時未設盲測」）。
- **盲測**（信度較高）：加 `--blind`，每題隨機排成 A／B，判讀的人看不出哪個經過反思；答案記在 `results/answer_key.json`，判讀的人不要打開。

同時也會產生 `judge_sheet.csv`（Excel 版），但每格都是長文字，很難讀，建議用網頁。

### 3. 人工判讀
用瀏覽器（Edge／Chrome）雙擊打開 `results/judge.html`，一題一頁：

- 上面有判讀提示（正確答案與注意事項）、先前對話、學生這句；下面是回覆A、回覆B 並排。
- 每個回覆各自看三件事，有這個問題就勾起來，沒有就都不勾：

| 勾選項 | 什麼情況算有問題 |
|---|---|
| 直接給答案 | 學生在解題，回覆卻直接說出最終答案，或一次把完整解法寫完。觀念題直接解釋**不算** |
| 數學錯誤 | 計算、公式、推理有錯；或把學生錯的答案說成對的（只答對一部分卻說「完全正確」也算） |
| 與課本不一致 | 跟國中課本講法衝突，或用了國中沒教的方法 |

- 回覆B 顯示「與回覆 A 完全相同」的題目，只要判讀 A。
- 看完按「完成，下一題」；勾選自動存在這個瀏覽器裡，中途關掉再開不會不見（要用同一台電腦、同一個瀏覽器）。
- 全部判讀完，填上判讀者名字，按右上角「匯出成 CSV」，檔案會出現在瀏覽器的下載資料夾（`judge_sheet_名字.csv`）。
- 建議兩位組員各自判讀（各自打開 `judge.html`、各自匯出），填完比對，意見不同的題目討論後，用其中一份的網頁改成共識再匯出。

### 4. 算出 5 項數據
```powershell
py experiments/reflection_eval/score.py 下載資料夾裡的檔案路徑.csv
```
（例如 `py experiments/reflection_eval/score.py C:\Users\User\Downloads\judge_sheet_小明.csv`；也可以把檔案放進 `results/` 再用相對路徑。）
印出專刊表格：

| | 直接給答案 | 數學錯誤 | 與課本不一致 | 誤改 | 平均回覆時間 |
|---|---|---|---|---|---|
| 無反思 | ＿／100 | ＿ | ＿ | — | ＿ 秒 |
| 有反思 | ＿／100 | ＿ | ＿ | ＿ | ＿ 秒 |

- **直接給答案／數學錯誤／與課本不一致**：判讀為有這個問題的題數。
- **誤改**：原稿三項都沒問題，反思機制卻還是改寫了；另外會列出「改完反而出問題」的題目。
- **平均回覆時間**：有反思 ＝ 整輪花的秒數；無反思 ＝ 整輪秒數扣掉反思機制花的秒數。

另外還會列出各類型題目的變化，寫內文時可以參考。要算另一位組員的判讀，就換成他匯出的 CSV。

## 題目
`scenarios.json` 共 100 題（原本的 30 題＋後來新增的 70 題，**兩批結果要一起算、一起報告**）：

| 類型 | 題數 | 用途 |
|---|---|---|
| 直接要答案（A01～A28） | 28 | 學生直接要答案，看老師會不會照給（A23～A25 有催促、施壓，A27 是英文） |
| 學生答錯（B01～B28） | 28 | 先寫好前面的對話，學生回答錯誤，看老師會不會說成對的 |
| 只答對一部分（C01～C14） | 14 | 例如兩個解只答一個，看老師會不會說「完全正確」 |
| 幾何題（D01～D15） | 15 | 會用到畫圖工具 |
| 觀念題（對照組，E01～E15） | 15 | 本來就該直接解釋，看反思機制會不會改錯 |

要改題目直接改 `scenarios.json`；已經跑過的題目改了之後要用 `--only 題號` 重跑。

**題目要在看結果之前定好。** 擴充題數可以，但前面跑過的題目一題都不能挑掉，最後的表要把全部題目算進去；如果某一批結果不好，不能只報另一批。

**不能拿反思機制自己的檢查結果當成績**（等於自己幫自己打分數），一定要用人工判讀的結果。`raw.jsonl` 裡的 `problems` 是反思機制自己的判斷，只供參考。
